# 乒乓球有效比赛检测 —— 原型

方案 V1.0「模块四」的可行性验证。**结论：方案里「第一版用音频能量 + FFT」的技术路线不成立，必须换。**

## 怎么跑

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

```bash
.venv/bin/python -m ppai.cli analyze /path/to/video.mp4
```

命令：`probe`（质量检测，对应模块二）、`analyze`（检测 + 出图 + JSON）、`cut`（切片拼接集锦）、`validate`（正负样本对照）。
所有阈值在 `config.yaml`，也可 `-s audio.k_mad=6.0` 临时覆盖。

## 已验证的结论

### 1. 检测器无法区分「击球声」和「任何有结构的声音」

拿一段**有声小说朗读**（零乒乓球）喂进去：

| 素材 | 内容 | 判定 |
|---|---|---|
| neg_speech | 《活着》纯人声朗读 120 秒 | 216 个"击球"，**100% 时间在打球**，置信度 1.00 |
| PP-video ×6 | 真实乒乓球视频 | 100% 时间在打球，置信度 1.00 |

两者输出完全一样。根因：`局部中位数 + k×MAD` 是**相对**阈值，只找"比周围响的东西"，
任何有结构的音频都有约 2 次/秒的起振越线。它没有任何「乒乓球」的先验。

跑 `validate` 可复现：

```bash
.venv/bin/python -m ppai.cli validate --pos "PP-video/*.mp4" --neg "negatives/*.mp4"
```

### 2. 手工声学特征救不回来

对每个候选峰算了 4 个冲击性特征，与阴性样本比可分性（AUC，0.5 = 无区分力）：

| 特征 | AUC | 乒乓中位 | 对照中位 |
|---|---|---|---|
| crest（波峰因数） | 0.667 | 1.69 | 1.01 |
| decay（衰减速度） | 0.369 | 0.51 | 0.77 |
| hf（高频占比） | 0.428 | 0.31 | 0.39 |
| flat（谱平坦度） | 0.457 | 0.58 | 0.60 |

最好的单特征只有 0.667。`decay < X AND crest > Y` 的二维门控扫了 9 组阈值，
**没有一组**能让正样本保持 >1.5 次/秒同时阴性降到 <0.3 次/秒——区间是重叠的。

### 3. `hit_count` 的语义待定

曾据「峰以 0.06–0.09 秒紧密成对出现」推测那是球拍触球 + 球台弹跳两声、
因而 `hit_count ≈ 挥拍数 × 2`。**这个推测已被人工核对否定**：
一次击球在声谱图上就是一道细的宽带竖纹，成对出现的是两次独立击球。

在拿到逐拍标注前，`hit_count` 只应理解为「声学瞬态数」。
模块五要用它算回合拍数，得先用标注对齐。

### 4. 工程部分没有风险

管线本身跑得很好：69 秒视频 2.1 秒处理完（约 33 倍速），一小时录像约 2 分钟。
FFmpeg 抽帧、切片、拼接、状态机、可视化都正常。**风险 100% 集中在"判断有没有在打球"这一步。**

### 5. PANNs 预训练嵌入解决了特异性问题

把 AudioSet 预训练的 CNN14 当特征提取器（1 秒窗 / 0.5 秒跳，2048 维），
在弱标签上训逻辑回归，**留一文件交叉验证 AUC 0.993、准确率 0.979**。

弱标签是免费的：6 个已剪辑短片全程在打球 = 正，有声书/无关视频 = 负。

| 留出文件 | 真值 | 判为打球比例 | 基线（谱通量）覆盖率 |
|---|---|---|---|
| 5 个乒乓球短片 | 正 | 79% – 100% | 100% |
| neg_misc | 阴 | **1%** | 86% |
| neg_speech | 阴 | **0%** | 100% |

**但这还不足以下结论。** 只有 2 个阴性文件，分类器可能只是在区分
「球馆混响 vs 室内朗读」，而不是「在打 vs 没在打」。真正的干扰源
（隔壁球台、场边说话、观众）一个都没进训练集。

内部检验（同一段录像里能否找出空闲）也没有定论：12 分钟真实录像判为
72% 打球，但概率曲线在 0.5–1 秒尺度上剧烈振荡，只有 2 处 >5 秒的空闲。
说明它学到的是「这 1 秒窗内有没有击球声」而非「这段时间在不在打球」——
回合中两拍之间的间隙就会让概率掉下去。要靠状态机平滑，且**必须有人工标注才能验证**。

## 下一步的三个选项

1. **换预训练音频事件模型**（方案里列为"升级"的 YAMNet / PANNs）。它们在 AudioSet 上见过大量撞击类声音，
   有真正的声学先验。这应该是 v1 而不是 v2。
2. **主要依赖画面**：球检测 + 追踪（YOLO 小目标）。音频降级为辅助信号。成本更高但天花板也高。
3. **先标数据**。上面所有调参都是盲调——没有一帧是有标注的。
   哪怕只标 30 分钟真实录像（打球/没打球），就能把"猜阈值"变成"测准确率"。

不管走哪条，**新方案必须先过 `validate`**：阴性素材覆盖率要接近 0。

## 素材现状

`~/Downloads/PP-video/`：

| 文件 | 规格 | 时长 | 用途 |
|---|---|---|---|
| `06a6c98c…` | **横屏 960×544** | 12 分钟 | 唯一接近方案假设的原始录像，**待人工标注** |
| `352e7b27…` | 竖屏 544×960 | 3.5 分钟 | 待标注 |
| 6 个 `video_…` 短片 | 竖屏 1080×1920 | 13–69 秒 | 已剪辑成片，全程在击球，只能当弱标签正样本 |

短片全程都在打，没有"等待、捡球"可删，**产品核心价值在它们身上无法体现**。
两个长视频是目前唯一能验证核心场景的素材，但还没有真值。

阴性对照放在 `negatives/`（不入库），用 `label-negative` 一条命令即可标完。

## 代码结构

```
ppai/
  audio.py     谱通量 + 自适应阈值（已证明不够用，保留作基线）
  motion.py    抽帧灰度帧差
  detect.py    信号融合 + 滞回状态机
  validate.py  正负样本对照（新方案的准入测试）
  viz.py       时间轴三联图，调参时肉眼校准用
  render.py    FFmpeg 切片 / 拼接
  embed.py     PANNs CNN14 音频嵌入（当前最优路线）
  labels.py    标注格式
  annotate.py  自包含 HTML 标注页
  evaluate.py  对着标注算准确率
  scene.py     场景判别
  cli.py       命令行入口
```

## 环境说明

需要 **Python >= 3.10**。Python 3.9 上 torch 最高只到 2.2.2（官方未再为 3.9 发布
macOS arm64 wheel），而 torch 2.2.2 不兼容 numpy 2.x —— 在 3.9 上无法让所有包都用最新版。
当前验证环境：Python 3.13.14 / numpy 2.4.6 / opencv 5.0.0 / torch 2.13.0 / scikit-learn 1.9.0。

PANNs 权重需手动下载一次（312MB），命令见 `ppai/embed.py` 顶部。
